# Fleet VOR Hub v1 — обновление уже работающего проекта

**Ветка:** продолжай работать в `feat/fleet-vor-hub-demo`; новая ветка не требуется.
**Адрес:** http://localhost:3000/fleet-vor-hub
**Пароль:** прежний пароль, по умолчанию `Victoria`.

## Как установить

1. Останови FastAPI в первом терминале (`Ctrl+C`) и Next.js во втором (`Ctrl+C`).
2. Находясь в локальной ветке проекта, проверь `git status --short`. Сохрани свои незакоммиченные изменения, если есть.
3. Распакуй **содержимое** ZIP в **корень** репозитория `alextym` c заменой файлов в папках `frontend`, `backend`, `scripts`. Другие папки сайта не изменяются. Новые файлы: `backend/app/services/vor_exports.py`, `backend/tests/test_vor_v1_update.py`, этот документ.
4. Если предыдущая версия уже работала, **не нужно повторять** `scripts/install_vor_hub.py` — API router уже зарегистрирован. Если ты ещё не запускал установщик, выполни `py -3 scripts/install_vor_hub.py`.
5. Из корня проекта запусти оба сервиса в отдельных PowerShell:

**Терминал 1 (backend):**

```powershell
.\scripts\start-vor-backend.ps1
```

**Терминал 2 (frontend):**

```powershell
.\scripts\start-vor-frontend.ps1
```

6. Открой http://localhost:3000/fleet-vor-hub, обнови страницу `Ctrl+F5`.

**Не удаляй** `backend/_local/vor_hub.sqlite3`! Сохраняются все пользовательские сообщения,
добавленные контакты, бронирования и шаги workflow. Миграция существующего файла запускается
автоматически при первой загрузке и выполняется один раз. Если ты менял состав подписчиков
в старой версии, в первый запуск установятся новые тестовые подборки 2–3 внутренних + 1 внешний
на автомобиль (состав только этой демо-функции сбрасывается один раз).

## Что изменилось

- Форма «Г»: панель Vehicles слева во всю высоту; выбранный автомобиль — большая выделенная
  карточка сверху над центральной нижней панелью и Chatter.
- Красноватый акцент — приглушённый `#B96063` вместо бордового во всех компонентах.
- Все идентификаторы тикетов: `PS000100`–`PS000139` (40 штук), в том числе ссылки в событиях.
- Из фильтров Chatter удалён `Service`; события обслуживания остаются в `All activity`.
- В левой карточке авто добавлен Workshop.
- Две IVECO заменены на Tesla Model Y.
- `Demo v3` → `Demo v1`; профиль содержит фото сайта `/images/profile/alex.webp`
  и полное имя `Alex Tymoshenko`.
- Пять демо-пользователей: `Alex Tym`, `Victoria B.`, `Jason W.`, `Janine M.`, `Gosha T.`.
- Три вымышленных похожих имени внешних партнёров: `Steve EXHAUSTON`,
  `John CITYSIDE GARAGE`, `Mark M&BRIDGE`.
- Excel: кнопка `↓ Excel` справа в header, скачивает настоящую таблицу `.xlsx`
  с листами `Vehicles`, `Tickets`, `Activity`, `Bookings`, `Subscribers`.
- Calendar: `↓ Download calendar (.ics)` — файл бронирований MOT, Inspection и Service,
  с датами и мастерскими, подходит для импорта в Outlook или Google Calendar.
- В редакторе сообщения удалён ряд `Link to`. Привязка идёт автоматически к текущему
  автомобилю и выбранному тикету в Chatter; `Vehicle only` доступен в его фильтре.
- Script `start-vor-backend.ps1` запускает `uv run --no-sync`, чтобы не повторилась
  ошибка Windows доступа к `backend/.venv` (в твоём окружении уже установлены зависимости).

## Проверка

1. Vehicles: выбранное авто находится в верхней широкой карточке; слева Workshop.
2. Vehicles: в Linked Tickets только `PS000xxx`; никакой IVECO.
3. Подписчики: 2–3 внутренних имени и 1 внешнее, разные по машинам.
4. Chatter: нет фильтра Service и ряда Link to.
5. Excel: открой файл, проверь пять листов и актуальность сообщений/бронирований.
6. Calendar: скачай ICS, импортируй в календарь, проверь гараж в Location.
7. Сообщения и вручную добавленные бронирования не исчезают после обновления страницы.

**Локальные проверки пакета:** `pytest` (API, миграция и экспорты); синтаксис TSX через TypeScript transpile. Полноценный Next.js production build в этом окружении не запускался; проверь на своём компьютере: `cd frontend; npm run typecheck; npm run build`.

## Экспорт в защищённом API

```
GET /api/vor/export.xlsx    -> application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
GET /api/vor/calendar.ics   -> text/calendar
```

В обоих случаях обязательна действующая сессия `/api/vor`. Экспорт использует актуальный
снимок SQLite; не добавляет возможности реальной отправки email.
