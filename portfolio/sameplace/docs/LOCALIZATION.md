# Localization

SP01 enables only `ru`. The translation dictionary is `frontend/src/i18n/messages.ru.json`; the typed translator and locale registry live in `messages.ts`. There is no global locale provider, global route rewrite, language cookie, document language mutation or language-dependent URL. `SamePlaceFoundation` uses a local `lang="ru"` section. The global website remains unchanged.

Use stable English dot-separated message keys. `resolveLocale` normalizes a language/region tag and falls back to `ru`; future locales can be added to the dictionary registry only when key coverage, placeholders and language-specific formatting are complete. User-visible text must come from a localized dictionary; do not translate identifiers, URLs, stored state, names or user chat. For module-owned keys use `activities.<module_id>.*`; module dictionaries and rules documentation will be independently versioned in SP05. No runtime external translation provider. Server errors later use stable machine codes and safe arguments; do not show raw internal errors.

The translator interpolates named arguments as text, with a safe RU fallback for invalid/missing keys and placeholders; strict mode raises in development/tests. React escapes text. `playerCount` uses `Intl.PluralRules` and `Intl.NumberFormat`, not English plural suffixes. Future date and number formatters must use selected locale/time zone without changing UTC state or arithmetic. Pseudolocale is injected only by tests; it is never published. A complete production translation system and accessibility review are incremental acceptance gates, not claimed by SP01.

File names containing Cyrillic content must follow the existing `.ru.` policy. The canonical Russian specification is `SAMEPLACE_FULL_TECHNICAL_SPECIFICATION.ru.md`. Ongoing engineering docs, identifiers and comments are English. Tests compile the actual translator and verify key uniqueness, fallback, plural forms, placeholders and pseudo translation isolation.
