# Media operations and private acceptance — SP05

Status: candidate, not publicly activated. SP05 introduces independent room-level P2P, not a game. Actual NAT coverage, device permissions, audio mixing quality, free hosting and capacity remain acceptance gates. SP06 Activity SDK and SP07 Preferans must demonstrate that their mount/unmount does not close the media provider.

## Ownership and runtime

`MeetingPanel` owns the local controller and local audio preferences. A `MediaProvider` interface isolates the P2P mesh implementation from the room view. The existing authenticated WS carries only addressed SDP/ICE and compact media state. The server's `MediaState` shares the Hub lock and atomically rotates pair identifiers when a permitted pair disappears. No video/audio frame, device ID, SDP, ICE, stats or media event is written to Firestore, logs or analytics. Media is opt-in, one publishing/receiving media endpoint per UID per meeting, regardless of two presence tabs. Camera and microphone are off at entry, and after disconnection/reauth loss require a new explicit action. Leave stops every local track and closes peer connections. Room-wide mode retains the pair on a change of location; local mode restricts pairs to occupants of the same location. Room owner, organizer or moderator may change the meeting policy. Owner/moderator may mute a participant; a delegated moderator cannot mute the room owner. The mute is meeting-local, not a permanent room ban; existing Room Core handles removal/block. Unmute restores permission only, never starts capture. No recording, mixing of music into microphone, remote control of camera or paid relay.

Fixed audio/video transceivers with a designated offerer avoid glare and renegotiation on normal track toggles. ICE may precede SDP; stale pair IDs are rejected. Browser congestion control plus requested 640x360/15 fps and a 300 kbps video sender cap are initial targets, not a quality guarantee. Failure is isolated from chat/room state; leave and rejoin manually to renegotiate. No automatic re-capture or retry storm. Direct peer-to-peer media exposes ICE network metadata to authorized peers; do not promise anonymity. Already-established connections cannot be forcefully terminated by the server against modified clients; compliant clients respond to revocation/updated peer state (nominally one second, plus network scheduling). Use an SFU only after separate architecture/cost approval if strict central media moderation is required.

Audio settings are browser-local, versioned and validated. Voices and music have active controls; ambient/game bus gains are reserved for actual sound sources in later stages, not fictional playback. Master mute covers both active outputs; ducking uses available RTC audio-level stats, approximate, browser-dependent. No audio-level telemetry to server. Camera/mic input preference and output device preference persist locally, no permission grants persist in code. `setSinkId` and element volume depend on browser support; use system audio selection/volume otherwise. Headphones recommended; browser AEC/noise suppression/AGC are requested, not an echo guarantee. Real Safari/iOS/Android testing is essential.

## Feature configuration and cost

Nothing enables itself on merge. Keep public production flags off until SP10 explicit release approval. A local isolated test is allowed after passing CI; a hosted private pilot at SP05 requires explicit Owner approval of the environment, provider budget/usage, private access, secure transport, and a tested stop switch. Prefer a preview frontend and an isolated demo/staging backend/Firebase with matching projects. Do not deploy a second billable Render service or create paid Firebase resources. If an isolated hosted environment cannot be provisioned with hard GBP 0, use local Emulator instead; do not silently enable the live website. Use an approved single instance and worker, no scale-out. Default media off; enabling media applies an actual room admission ceiling of 2 by default, separate from the configured room/policy limits. Raising `SAMEPLACE_MEDIA_CAPACITY` (2–10) is only for an explicitly approved progressive test or after measured acceptance, never proof of capacity. Existing meetings over the limit cannot start new media endpoints. no TURN or SFU runtime, no implicit public STUN. Set a specific approved STUN URI only if its terms and connectivity have been verified. Missing/invalid STUN config yields host candidates only (often fails across NAT). Do not add TURN credentials or paid fallback based on a free allowance alone.

| Scope | Environment variables |
|---|---|
| Both frontend and backend | `PORTFOLIO_LAB_ENABLED=true`, `SAMEPLACE_ENABLED=true`; matching Firebase project and existing valid server/browser Firebase config |
| Backend only | `SAMEPLACE_REALTIME_ENABLED=true`, `SAMEPLACE_REALTIME_SINGLE_WORKER=true`, `WEB_CONCURRENCY=1`, `SAMEPLACE_REALTIME_ORIGINS=<exact frontend origin>`, `SAMEPLACE_MEDIA_ENABLED=true`, `SAMEPLACE_MEDIA_CAPACITY=2` |
| Optional backend only | `SAMEPLACE_STUN_URL=stun:<approved-host>:<port>`; leave unset for local/host-candidate smoke. No secrets in this value. |
| Frontend server | `BACKEND_ORIGIN=<actual backend HTTPS origin>` (loopback HTTP local only), `PORTFOLIO_LAB_ORIGIN=<exact frontend origin>` (required for Vercel); existing Firebase public and server configuration as in Lab |

Use exact lowercase `true`, not `1` or `True`. Never replace the existing Lab Owner UID or existing production Firebase credentials for a test. For local Emulator use local demo project (`demo-...`) and both local Auth/Firestore emulator hosts; verify existing Lab setup before starting. Never run emulator tests against production. Production origins must be HTTPS/WSS. Rollback: set `SAMEPLACE_MEDIA_ENABLED=false` and restart/redeploy the backend, then disable SamePlace realtime/feature if needed. Do not delete persistent rooms or regenerate the legacy freeze. No automatic env change or remote deployment is part of SP05.

## Private two-user walkthrough (after SP05 CI and approval)

1. Start the approved isolated test environment with the flags above. For local developer use, start the already configured Auth/Firestore Emulators, run `uv run --locked uvicorn app.main:app --host 127.0.0.1 --port 8000` in `backend`, and `npm run dev` in `frontend`; set matching backend/frontend configuration in their respective environments. On localhost the URL is `http://localhost:3000/portfolio/sameplace/rooms`. Hosted URL is `<approved-preview-origin>/portfolio/sameplace/rooms`. The intended production URL after explicit activation is `https://alextym.com/portfolio/sameplace/rooms`, not an assertion that it is currently reachable.
2. Sign in as the authorized Owner; create a private room with slug `media-test` and capacity **2** (or another unique slug). Do not use real personal data for isolated testing. Open the room URL `/portfolio/sameplace/r/media-test` on the same environment. Owner account can create rooms; other creators require Owner approval.
3. Register or sign in with a distinct guest account with verified email (use the emulator verification flow or already verified account). In the Owner room, create a targeted invitation for that email/UID and send the fragment link privately. The guest opens the invitation in a separate browser profile/device, authenticates, redeems, and enters the same permanent room. A room invitation does not grant other portfolio project access.
4. Wait until both users see each other in the room. Click **Join communication** on both clients. Click **Enable microphone**, permit browser capture, then **Enable camera** if desired. Use headphones. Both users must be separate Firebase identities; two tabs of the same UID are not two participants. Camera/mic permission is voluntary. Use the retry-audio button if autoplay was blocked.
5. Check voice in both directions, video frames, mute/unmute, music volume and ducking, changing scene and magnetophone, chat and location mode. Room-wide voice must survive a location/scene change. In local mode move one participant to the other location and verify audio/video disappear; move back and reconnect. Moderator mute must stop capture; permission restore must not turn the microphone back on. Try duplicate UID tab, browser refresh, denied permission, revoked membership, leaving the room, and disabled media. End with no active browser camera/mic indicators. Record any failure; do not infer a passed test from a successful build.
6. Repeat on two real devices on different networks (home Wi-Fi and mobile data). If direct ICE fails, report that limitation; do not quietly enable relay. Then test 3, 4, 6, 8, 10 only as actual device/network capacity permits. Measure RTT, loss, incoming bandwidth, upload, CPU/RAM, echo, freezes, Firestore usage and current host quotas. Stop on instability or quota thresholds; lower effective room capacity to the last verified level. A two-person pass does not validate ten people or free operation for hours. If even two fail across NAT, leave media disabled for that environment and review TURN hard cost cap/alternate design with Owner.
