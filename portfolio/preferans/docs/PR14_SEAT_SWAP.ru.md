# PR14.B1 — единогласная перестановка мест до первой раздачи

База `50eddd404fa5e320f04da58c942d13b426e9de71`; PR14.A слит, Owner подтвердил локальный CI. Новый отдельный PR `feat/preferans-seat-swap`. Правило из HOUSE_RULES, §13: до начала партии можно поменяться местами по согласию всех троих. Не переписываем очередность торговли, расчёты, исторический ledger или привязку администратора к UID.

## Контракт

Действия через существующий защищённый POST `/api/preferans/rooms/{id}/commands`, с expected_version и idempotency_key. Новый URL не требуется. Доступ только участникам полного лобби с `lobby_setup` и ещё без первой раздачи.

| Action | args | Поведение |
|---|---|---|
| `seat_swap_offer` | `to`: номер другого места 0..2 | Предлагающий уже согласен; одна активная перестановка |
| `seat_swap_vote` | `id`: целочисленный ID предложения, `approve`: boolean | Отказ любого отменяет предложение; третье согласие выполняет перестановку |

Публичная проекция `seat_swap={id,from,to,votes}` только участникам лобби. `seat_revision` — монотонное необязательное поле в проекции участника (для legacy отсутствует), увеличивается при перестановке. Ни один UID не возвращается. Голосование привязано к текущей версии комнаты; повтор идентичной операции обрабатывает существующий idempotency ledger. Не принимать голос вместо другого игрока; устаревший ID, повторный голос и новая заявка при ожидающем предложении отклоняются. Начало партии, изменение правил и подтверждение готовности до решения предложения блокируются сервером. Отказ не изменяет текущую конфигурацию. У предложения нет искусственного таймера: его может отклонить любой из троих. Это инженерный выбор.

После третьего согласия в одной Firestore транзакции меняются только два UID в seats, номер первого сдающего пересчитывается, сохраняя выбранного человека, готовность сбрасывается для всех. Администратор остаётся прежним UID. До первой раздачи ledger ещё пуст; активная или законченная партия никогда не переставляет места. Событие содержит номера мест до перестановки и outcome, не UID. При неуспешном commit старые соединения остаются действительными.

## Realtime и профили

После успешной транзакции, под существующим single-worker commit lock, все tickets/leases/views и эфемерный live relay этой комнаты инвалидируются; соседние комнаты не затронуты. Старый WS завершает работу с recoverable 4408, уже предъявленный старый ticket не может зарегистрировать иной seat. Для все ещё seated UID с изменившимся seat это recoverable reconnect, не отзыв доступа. Frontend штатным HTTP fallback получает актуальный seat, перезапускает WS и обновляет профили по seat_revision. Смена только seat, не UID. Медиасессия останавливается; после reconnect игрок входит в звонок вручную. Не применять изменения топологии к играющей комнате. Legacy rooms без readiness marker не мигрируются автоматически.

## Проверки

Изолированно: 17 Python cases (pure consent + reconstructed hub from earlier source overlays), 8 TypeScript model assertions, ES5 strict model compile, точные blob IDs и anchors текущего main. Результаты полного CI, transactional FakeDB integration, Firebase Emulator, actual WS reconnect and browser rendering ещё не получены для этого кандидата. `test_seat_swap_store.py` проверяет actual store, отказ в преждевременном старте, outsider, idempotency, revoke only after commit, stale ticket, уникальные приватные руки после перестановки. E2E model test дополняет существующую Playwright suite.

Реальная приёмка: три аккаунта, все готовы; A предлагает обмен с C, B отказывает — места/готовность неизменны. Повторить и согласиться троим; ожидать новый seat всех трёх, обновлённые имена, новый WS, отключение медиасессии, готовность 0/3. Подтвердить и начать; проверить, что тот же человек сдаёт, правильная левая/правая ориентация, 30 разных закрытых карт, прикуп закрыт, администратор тот же. Проверить несколько перестановок, конфликт двух предложений и stale ticket; повторить без realtime. Не менять production flags без отдельного разрешения. G02b закрывается только после проверки. Случайное раскрытие, выбор условных наказаний, полный редактор наборов и архивирование остаются отдельными задачами.
