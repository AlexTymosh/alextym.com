# PR 9 — приёмка на трёх аккаунтах (обязательные доказательства)

**Нельзя автоматически поставить PASS:** unit-тесты и Playwright без Firebase Emulator не доказывают реальную авторизацию или приватность. Отмечай пункты после проверки и сохраняй дату/браузер/результат. Логи не должны содержать UID, cookies, SDP, ICE, закрытые руки, service-account JSON.

## A. CI и релизная сборка

- [ ] `task repo:check`, `task backend:check`, `task frontend:check`, `task ci` успешны локально.
- [ ] В GitHub Actions зелёные jobs `project`, `backend`, `frontend`, `rag`, `docker` для точного SHA PR 9.
- [ ] В Next.js build логах и статических файлах нет приватных ключей и незадокументированных эндпоинтов Preferans.
- [ ] `PREFERANS_MEDIA_ENABLED` и `NEXT_PUBLIC_PREFERANS_MEDIA_ENABLED` выключены в production до медиа-UAT.

## B. Firebase Auth / Grants / API

- [ ] Три отдельные сессии с грантами `Test`/`Admin`, один `View`, один без гранта.
- [ ] Неавторизованный/`View` не может POST создать комнату или послать ход; прямой Render origin также проверяет подпись Firebase и проектный грант.
- [ ] Каждый видит только свою закрытую руку; GET `/view`, `/events`, `/media`, `/invitation`, `/history`, `/rankings` не раскрывают UID и закрытые карты.
- [ ] SDP/ICE адресату доступны только по его комнате и месту; другой игрок и сторонний Owner не получают чужие сигналы.
- [ ] При отзыве проектного гранта последующие ответы запрещены, и старые приватные данные не продолжают показываться в браузере.
- [ ] Firestore Rules по-прежнему запрещают чтение/запись SDK-клиентом.

## C. Полная партия и математика

- [ ] Игрок А создаёт комнату, Б и В входят по ссылке; проверены занятые места и невозможность четвёртого участника.
- [ ] Торговля, «здесь» (кроме 6♠), прикуп, снос, заказ окончательного контракта, вист/пас/полвиста, светлая и тёмная игра проверены живыми пользователями.
- [ ] До 10 взяток, окончание сдачи, запись в пулю/гору/висты, распасы и редкие граничные правила совпадают с документом `HOUSE_RULES.ru.md`.
- [ ] Таймер, повторный штраф, пауза из-за отсутствия, единогласная отмена последней карты/ставки, сохранение аудита проверены при одновременных действиях.
- [ ] После закрытия партии нет возможности изменить результат через API; одна финализация = одна история, без повторных медалей.
- [ ] Игровые действия не зависят от доступности WebRTC.
- [ ] Необработанные сценарии «выбросить листик», подмена голых ударов, редактор правил и ошибочное раскрытие либо реализованы отдельным PR, либо явно исключены из релизного обещания пользователям.

## D. Медиа и запись (только отдельное staging включение)

- [ ] Три устройства/сети: Chrome desktop, Android Chrome, Safari/iOS или другой задокументированный набор; сработали 3 двусторонних канала.
- [ ] Каждый может независимо запретить камеру/микрофон; игра остаётся работоспособной.
- [ ] Запись не стартует без 3 явных согласий; UI показывает статус всем участникам, любой может отозвать согласие.
- [ ] Выключение сети у инициатора, уход вкладки в background, отказ polling и смена комнаты прекращают запись; локальный файл воспроизводится.
- [ ] Записанный файл содержит только общий стол и разрешённые медиапотоки; закрытые карты не попадают в видео/аудио.
- [ ] Звук трёх участников действительно попадает в итоговый файл, не возникает пустых дорожек и двойного эха.
- [ ] Полный сценарий без TURN: проверены ограничения различных NAT и пользовательская ошибка, не блокирующая игру.
- [ ] Измерены реальные reads/writes Firestore для 1/2/3 часов игры. Убедись, что с остальными сервисами не превышен бюджет.
- [ ] Прогон ручной очистки сначала dry-run, затем apply на эмуляторе. В production только после проверки project ID, квоты и операционного графика.

## E. Мобильность, доступность, возврат и откат

- [ ] Интерфейс 360/640/900/1280 px без горизонтального скролла; фокус клавиатуры, доступность кнопок и drag fallback.
- [ ] Смена соединения, reload браузера, продолжение игры по коду комнаты без рассинхронизации версии и дублирования действий.
- [ ] Отказ доступа к микрофону, перебой Render/Firestore, timeout API показаны пользователю и не раскрывают секреты.
- [ ] Проверена отключающая конфигурация: `PREFERANS_MEDIA_ENABLED=false` / `PREFERANS_ROOMS_ENABLED=false`; публичная часть сайта, Fleet и Workforce по-прежнему работают.
- [ ] Есть документированный оператор, который сможет повторить cleanup и rollback без помощи разработчика.
