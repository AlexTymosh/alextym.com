# PR 8 — добровольная связь, запись по согласию и ностальгический интерьер

**Основа:** PR #274 merged to `main` at `4f88428e539fbe979f407d83f617ebc76a3b33d4`.

## Что реализовано

- `GET/POST /api/preferans/rooms/{room_id}/media`: авторизованный обмен сигналами только **между тремя занявшими места** игроками, без права доступа глобального Owner-наблюдателя. Сигналы SDP/ICE читаются только адресатом; срок видимости 90 секунд, максимум 64 сигнала в документе. Идентификаторы Firebase и закрытые руки не возвращаются.
- Firestore Admin SDK создаёт `preferans_rooms/{id}/media/current` и `media_operations/{hash}`. Никаких записей медиа на сервере. Клиентские Firestore Rules остаются deny-all.
- WebRTC mesh: максимум два peer-соединения на игрока. Раздельное разрешение микрофона/камеры, отказ от участия не мешает игре. Используется публичный STUN `stun.l.google.com:19302` **без SLA/гарантии стоимости и доступности**; TURN не настроен, сложные NAT/корпоративные сети могут не соединиться. STUN и другие участники соединения могут видеть сетевые IP-метаданные.
- Запись `MediaRecorder` на устройстве инициатора из `canvas.captureStream(15)` + смешанный `Web Audio`. В canvas **только общий стол и текущие открытые сыгранные карты**, не закрытые карты, прикуп или личная рука. Видео игроков, у которых включена камера, отображается с их разрешения. При штатном завершении браузер предлагает файл `.webm` или `.mp4` (по поддержке кодека).
- Инициатор выражает собственное согласие `record_request`, два остальных соглашаются через `record_vote`, только после трёх `true` возможно `record_start`. Статус записи виден каждому. Любой `record_stop` или отказ переводит запись в stopped. Состояние не влияет на доменный игровой движок.
- Без персональных фотографий: сгенерированный пустой интерьер `nostalgic-room.webp` в CSS-слое локального проекта. Медиапотоки на фоне не сохраняются.

## Feature gates

Ничего не включается автоматически. Для локального UAT совместно требуются:

- `PORTFOLIO_LAB_ENABLED=true`, `PREFERANS_ROOMS_ENABLED=true` — прежние настройки;
- `PREFERANS_MEDIA_ENABLED=true` — отдельно **в backend и Next.js**;
- `NEXT_PUBLIC_PREFERANS_MEDIA_ENABLED=true` — только публичный переключатель UI в Next.js;
- Auth/Firestore Emulator или защищённая тестовая Firebase-конфигурация; три отдельных аккаунта с проектным грантом `Test`/`Admin`.

Настройки `PREFERANS_MEDIA_ENABLED` по умолчанию выключены. Для браузерных камеры/микрофона нужен HTTPS или `localhost`, а также явное разрешение устройства.

## Ограничения и защита данных

1. **Мгновенная остановка при отзыве согласия на расстоянии НЕ доказана**: сигнал через data channel — best effort, резервный опрос Firestore каждые 2,5 секунды при активном медиа. При разрыве сети задержка может быть больше; это блокер production до приёмки. На устройстве отозвавшего запись останавливается немедленно. Готовый отрезок уже записанного файла нельзя дистанционно удалить.
2. Firestore сохраняет **сигнальные метаданные SDP/ICE** (потенциально IP-адреса) в ограниченном окне 90 секунд на чтение, но старые записи физически удаляются только при следующем сигнале. `media_operations` пока не имеют автоматической TTL-очистки, даже несмотря на отсутствие аудио/видео. Нужна серверная политика хранения/очистки на PR 9.
3. `MediaRecorder`/AudioContext/Canvas и входящие автоплей-потоки различаются по браузерам. Без реального теста iOS Safari, Android Chrome, desktop Chrome/Firefox нельзя обещать воспроизводимый файл и корректное аудиосведение.
4. Если другой участник подключится после старта записи, его аудио не гарантированно включится в уже созданный Web Audio mix. Требуется тест/исправление до релиза.
5. WebRTC renegotiation при переключении устройств и ICE restart — best effort, не гарантируются в сети с ограничениями. В случае сбоя игра продолжает работать, но медиа может быть недоступно.
6. Polling media-state ~2,5 с при активном соединении, ~12 с без него; presence heartbeat ~25 с. Для трёх игроков это создаёт Firestore reads/writes; бюджет £0 необходимо подтвердить **измерениями**, а не предполагать.
7. Права доступа на сайте (View/Test/Admin) и прямом Render origin должны тестироваться отдельно. UI-флаг не является проверкой безопасности; backend самостоятельно проверяет Firebase и членство в комнате.

## Безопасность

- Не публиковать ICE/SDP в аналитике, логах и публичных событиях комнаты. Фронтенд отправляет только через Next.js BFF с session cookie и same-origin guard.
- Никогда не сериализовать private GameState в медиаканал. В записи рисовать только отдельно переданную public scene, не делать `screenCapture` вкладки.
- Нельзя обещать абсолютную защиту от внешней записи экрана пользователем вне приложения.
