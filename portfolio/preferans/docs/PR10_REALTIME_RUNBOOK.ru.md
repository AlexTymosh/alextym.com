Повторить при undo vote, закрытии вкладки, network silence, restart. Нельзя возобновлять игру, пока остаётся другая причина паузы. Shared overlay/break ещё не реализованы.
5. Зафиксировать 6 ч нормальной нагрузки/8 ч reserve в PR14. В PR10 сначала короткий representative run: p50/p95/p99 commit-to-render; reads/writes, retries, память, количество snapshots. Длительный прогон только на разрешённой тестовой среде, без биллинга. При budget failure не включать production. Не запускать дорогой live нагрузочный тест автоматически.

## Расходы — модель, НЕ замер
Три игрока × 6 ч × 3600/15 = 4320 WS heartbeat сообщений; hub heartbeat не делает DB операций. Reauth раз в 60 с = 1080 проверок на троих, каждая включает существующие identity/grant и проверку room; cold/ticket/reconnect add reads. В здоровом канале нет прежних view polls и pulse events. При 1760 принятых командах минимально 5280 transaction reads, 7040 writes (3/4 на команду), дополнительные auth, история, settlement, retry, sync/checkpoints и media увеличивают итог. Точный A×D зависит от партии. При активных часах checkpoint не чаще ~60 с без transition; no clock/no transition — нет синхронизационной записи. HTTP fallback медленнее (20 с view + 45 с presence), не режим для бесконечного игрового soak без контроля. `GET /api/preferans/realtime-metrics` через BFF только Owner: накопленные локальные минимальные оценки, сбрасываются при restart, не включают все provider operations. Сопоставить с общими Firebase usage/Render/Vercel usage; целевые 15k reads /10k writes за 6 ч, дневные free quotas общие с сайтом. Без подтверждения фактического остатка и тарифа £0 не гарантируется.

## Включение только после отдельного разрешения Owner
Render: проверить 1 instance, 1 worker (`WEB_CONCURRENCY=1` или default один), существующие `PORTFOLIO_LAB_ENABLED=true` и `PREFERANS_ROOMS_ENABLED=true`; выставить `PREFERANS_REALTIME_ENABLED=true`, `PREFERANS_REALTIME_SINGLE_WORKER=true`, `PREFERANS_REALTIME_ORIGINS=https://alextym.com` (для staging явный точный origin, без wildcard). Vercel: `PREFERANS_REALTIME_ENABLED=true` и `NEXT_PUBLIC_PREFERANS_REALTIME_ENABLED=true`; сохранить существующий backend origin/session config. После redeploy проверить CSP допускает configured `wss://` Render (при блокировке зафиксировать ошибку и узко исправить после аудита, не ослаблять CSP целиком). Проверить браузерный Network WS 101, snapshots, ping/pong, отсутствие регулярных view/pulse в healthy path. Не менять Firebase billing, IAM, TTL, TURN, другие проекты. Медиа оставить с прежними флагами, для теста PR10 предпочтительно off. При включении медиа ранее существовавший recorder не изменён этим PR.

## Откат
Отключить обе realtime серверные переменные включения и `NEXT_PUBLIC_PREFERANS_REALTIME_ENABLED`, пересобрать Vercel; оставить базовые room flags как были. Остановить активные тестовые игры безопасно до переключения; не удалять Firestore state. Проверить старый polling, восстановление комнаты, отсутствие новых ошибок. Дополнительные поля controls совместимы с прежним форматом при корректном состоянии; при активном замороженном таймере до rollback проверить remaining/deadline, не принудительно начислять штраф. При необходимости rollback deployment на проверенный SHA с сохранением SDK repair. Никаких автоматических миграций/очисток production.
