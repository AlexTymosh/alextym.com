# PR 3 — денежная математика преферанса по-запорожски

**Источник правил:** `HOUSE_RULES.ru.md`, разделы 5–12, и `FULL_TECHNICAL_SPECIFICATION.ru.md`, разделы 8–14 и 25. Это именно расчёты семейного варианта; общепринятый «преферанс» не является источником альтернативных значений.

**Исходный код:** `backend/src/preferans/domain/{rulesets,ledger,scoring,settlement}.py`. Реализован без Firebase, API, хранения, времени и внешних библиотек.

## 1. Границы и модель

- После `GameState.phase == FINISHED` вызывается `settle_game(ledger, game, deal_id, ...)`. Ни `GameState` (закрытые карты), ни прикуп не переносятся в `ScoreState` или `LedgerEntry`.
- Возвращается **новое** неизменяемое `ScoreState` (пуля / гора / направленные висты / append-only числовые записи); при ошибке старый остаётся прежним.
- Идентификатор `deal_id` не может быть учтён второй раз; есть `expected_version` для будущего конкурентного сервера. Не путать с полноценной Firestore-идемпотентностью PR 4.
- Содержимое правил фиксируется через `freeze_ruleset(Ruleset(...))` и канонический SHA-256. Весь математический расчёт ведётся **целыми числами**. Запрещены float, отрицательная гора, переполнение пули и висты «на себя».
- `ScoreState.closed` становится `True` только после полного расчёта сдачи, закрывшей **все три** пули. Новая сдача затем не может быть рассчитана.
- Разделение на `POOL`, `HILL_FIRST`, `HELP` сделано явным. Нельзя бесконтрольно дробить начисления между направлениями.

## 2. Формулы

| Событие | Результат |
|---|---|
| Успешная обычная 6/7/8/9/10 | +2/4/6/8/10 положительных очков |
| Недобор заказчика | `(заказано - взято) × C` в гору |
| «Без трёх» до первого хода | `3 × C` в гору заказчику **без** консоляции и обычных вистов |
| Мизер (с прикупом и без) | 0 взяток ⇒ +10; иначе `10 × взяток` в гору |
| Взятки при одном вистующем | Все взятки **обеих** рук защиты × `2C` одному вистующему |
| Взятки при двух вистующих | Только собственные взятки × `2C` каждому |
| Консоляция | Обоим защитникам (включая пасовавшего) `2 × C × недобор` |
| Полвиста / оба пасуют на 6/7 | 8 вистов дальнему (второму) защитнику |
| Распасы 6/7/8 | В гору +1/+2/+3 за взятку, за ноль взяток +1/+2/+3 положительных очка |
| Закрытая пуля / помощь | +10 вистов на получателя за 1 очко помощи |
| Равные незакрытые пули и неделимое одно очко | +5 вистов на каждого соперника, **не** 0.5 в пулю |
| Нет незакрытых пуль / остаток последней сдачи | +5 вистов на каждого соперника за 1 очко |

### 2.1. Недобор защиты

- Один вистующий: `max(0, норма - всего защитных взяток) × C` в его гору. Нормы на 6/7/8/9/10: **4/2/1/1/1**.
- Два вистующих: общие нормы **4/2/2/1/1**. На 6/7/8 с личной нормой `q = 2/1/1` персональный недобор: `max(0, q - свои - max(0, чужие - q))`. Это **выведенная** формула из таблицы утверждённых примеров, не отдельный исторический ответ.
- Два вистующих на 9/10: при отсутствии защитных взяток оба пишут полный `C` в гору. При хотя бы одной общей взятке этой санкции нет (обобщение на основе общей нормы).
- При проигрыше заказчика штрафы защитников за несоблюдение обязанности **не отменяются** консоляцией: записи независимы.

### 2.2. Положительные очки, помощь

1. Обычная игра: сначала заполнить собственную открытую пулю. При закрытой пуле доступен выбор списания горы или помощи; остаток распределяется по существующим правилам.
2. Распасы: если бонус достигает собственной открытой цели — **сначала** закрыть пулю, затем выбрать, погасить ли гору или помочь. Если пуля уже закрыта — выбор горы или допустимой помощи; при блокировке помощи гора гасится обязательно, остаток конвертируется в равные висты. При недостаточном бонусе — только собственная пуля.
3. Помощь идёт более заполненной незакрытой пуле, если её владелец не получил штраф в гору за результат раздачи. При равных пулах исключаются оштрафованные; два допустимых получателя делят целые очки поровну, нечётный остаток превращается в 5+5 вистов. При блокировке помощи списывается собственная гора, остаток — равные висты. Если все пули закрыты, остаток — равные висты.
4. Когда два игрока получили ноль взяток на распасах, порядок двух бонусов **не указан историческими правилами**. Здесь он должен явно задаваться параметром `passout_reward_order`; без параметра расчёт отказывает, чтобы не создать молчаливый порядок. Порядок следует согласовать до PR 4.

## 3. Финальная математика

Для накопленной **всей** горы `H_i` один раз вычисляется `G_i = round(10H_i / 3)`, с целочисленным математическим округлением. Результаты:

`R_i = Σ(j≠i) (W_ij − W_ji + G_j − G_i)`; `ΣR_i = 0`.

Контрольные векторы: гора `[2,0,0]` ⇒ `[-14,+7,+7]`; гора `[0,3,6]` ⇒ `[+30,0,-30]`. `0,0,0` ⇒ без золотых; `10,10,-20` ⇒ два первых места.

Для каждой неупорядоченной пары: `ceil(|R_i−R_j|/50)` условных обычных ударов проигравшему; каждые 10 могут стать голым, с правом замены на 10 обычных. «Выбросить листик» — **особый** исход (два голых по одному от противников и два первых места у противников), не обычный нулесуммовой финал незакрытой партии.

## 5. Что сознательно отложено

- **PR 4:** безопасная интеграция результата с Firestore и Firebase permissions; транзакции + идемпотентность на сервере; приватные проекции.
- **PR 5:** UI выбора направления начисления и объявления обязательного порядка двух бонусов распасов.
- **PR 6:** фиксация 180-секундных штрафов, редактируемые admin corrections, аудит корректировок активной партии, отмены с голосованием и признания штрафных взяток на мизере. В PR 3 нет часов, пользователей и доступа к сети.
- **PR 7:** неизменяемое сохранение итогов и статистики ударов/медалей. Здесь готовы только чистые функции расчёта и предварительные выплаты.

**Неоднозначности до публичного запуска:** порядок двух бонусов распасов; нужно ли после автоматической победы при двух пасах сбрасывать ступень распасов к 6 (сейчас сбрасывается **только после реально разыгранного успешного обычного контракта**); допустимость автоматического переноса бонуса из полностью погашенной горы в ещё открытую пулю. Эти трактовки документированы и подлежат подтверждению, а не представляются как подтверждённые исторические правила.

## Дополнение PR18 — анимация и объявление «Без трёх»

Актуальное уточнение владельца правил: «Без трёх» разрешено только в фазе объявления окончательного контракта, до любого решения защиты. Команда `without_three` не требует заявки: сервер берёт выигранную ставку, завершает сдачу и атомарно записывает 3 × стоимость в гору, без перехода к вистованию. Старый аргумент `bid` допускается только при точном совпадении с выигранной ставкой. Формула штрафа и запрет мизера остаются прежними. Это заменяет старые указания «до первого хода». Визуальные изменения, ручная раздача очередным сдающим, пулька и критерии приёмки — в `PR18_TABLE_POLISH.ru.md`.

## PR24 — приоритет помощи

`reward_routing.py` определяет штрафы результата и допустимые приоритетные пули. `scoring.py` начисляет штрафы защитников перед наградой заказчика. При блокировке помощи — списание собственной горы и равные висты за остаток. Для распасов собственные бонусы стадируются одновременно; выбор каждого игрока сохраняется сервером. `all_mine_accepted` учитывает реальные взятки и отдельно присуждённый остаток, без фиктивных карт. См. `PR24_CLAIMS_AND_SCORING.ru.md`.

### Итоговый листик (PR25)

При нормальном закрытии пули сервер отдаёт участникам `final_settlement`: знаковая матрица попарных взаиморасчётов и общий итог каждого игрока. Значения вычисляются из существующей формулы `net_results`, с тем же округлением полной горы. Положительное число — игроку должны, отрицательное — он должен. Сумма итогов равна нулю. UI не пересчитывает финансовые итоги; техническое поражение и архивирование не формируют фиктивных итогов.

### PR30 — погашение горы и проверка итогов

Погашать собственную гору положительной наградой можно только после закрытия собственной пули. На распасах сначала зачисляется обязательная часть бонуса в пулю; при наличии остатка действуют ранее согласованные правила выбора помощи или списания. Финальная раскладка горы — серверная проекция `final_hill_vists` с прежним точным округлением, а не новая проводка. Висты отображаются как исходный баланс + расписанная гора = сумма; затем рассчитывается ранее существующий знаковый парный результат. Корректировки горы и вистов можно повторять до явного подтверждения итогов. После подтверждения опубликованный результат остаётся неизменяемым.

### PR32 — условные удары на итоговой пульке

Сервер использует тот же `placement_outcome`, что и история и рейтинг: разница общих итогов, округление вверх до каждого начатого интервала 50 вистов, исключение второго места без отрицательных парных балансов и замена голых обычными. В режиме проверки итогов отметки предварительные и пересчитываются после корректировки. При нормальной финализации базовые удары сохраняются в уже существующей транзакции комнаты. Старые комнаты без снимка используют текущую формулу и сохранённые варианты замены; исторические документы не переписываются. `final_punches` — read-only проекция только для участников нормального финала. Красные метки на листике показывают направление от начислившего к получившему условные удары, поворачиваются вместе с листиком и не видны при просмотре прежней записи. Техническое поражение не превращается в фиктивный финансовый расчёт.

## PR39

«По своим» распределяет оставшиеся взятки по согласованному итоговому числу у единственного вистующего. Действующие формулы пули, горы и вистов, история реально сыгранных взяток и маршрутизация помощи не меняются. Сервер повторно проверяет распределение при расчёте.
