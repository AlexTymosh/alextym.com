# Preferans — изолированный игровой движок (PR 2)

**Статус:** доменная реализация PR 2; не означает, что игра доступна через сайт.
**Основание:** `FULL_TECHNICAL_SPECIFICATION.ru.md` §§4–8, 10–11, 25, 33; `HOUSE_RULES.ru.md`.
**Ветка:** `feat/preferans-engine` от `main` после PR #268 (`e7a2a6dd519b852d2c640cb7d1b8170f89baec4a`).

## 1. Зачем нужен отдельный движок

Это чистые функции Python без Firebase, FastAPI, Firestore, таймеров, HTTP и веб-интерфейса. Каждая команда получает **неизменяемое предыдущее состояние** и возвращает **новое**. При ошибке выбрасывается `RuleViolation` и прежний объект не меняется. Это основа для будущих транзакций и повторяемых тестов. Впоследствии авторитетный сервер должен проверять `expected_version` и `idempotency_key` до записи полного секретного состояния.

### Файлы

| Модуль | Ответственность |
|---|---|
| `cards.py` | 32 карты, криптографический shuffle по умолчанию, пакетная раздача 2+2, прикуп после первого круга |
| `auction.py` | 32 упорядоченные ставки, мизер, десятирная без прикупа, первый ход торгов, пас, «здесь», итоговый минимум |
| `game.py` | Фазы партии: прикуп, скрытый снос, окончательный контракт, защитные решения и карточный розыгрыш |
| `play.py` | Следование масти, обязательный козырь, взятка, принудительная масть прикупа на распасах |
| `__init__.py` | Предназначенная для тестов публичная поверхность чистого движка |

## 2. Модель фаз

```text
AUCTION
  ├─ все пасуют → PLAY(passouts)
  └─ торги выиграны
       ├─ с прикупом → DISCARD → DECLARE
       └─ без прикупа ─────────→ DECLARE
                                    ├─ мизер → PLAY
                                    ├─ 6♠ → PLAY (оба вистуют)
                                    └─ иная игра → DEFENSE_FIRST → DEFENSE_SECOND
                                                         ├─ оба пасуют → FINISHED
                                                         ├─ полвиста → DEFENSE_RECONSIDER
                                                         │                 ├─ пас → FINISHED
                                                         │                 └─ вист → single-vist
                                                         ├─ оба вистуют → PLAY
                                                         └─ один вистует → single-vist

single-vist:
  ├─ первая рука = заказчик → OPENING_LEAD → CHOOSE_MODE → PLAY
  └─ первая рука = защитник → CHOOSE_MODE → PLAY

PLAY → 10 завершённых взяток → FINISHED
```

Не объединять торговый выигрыш и объявление контракта: после победы на **7♣** допустимы `7♣/7♦/7♥/7NT` или обычная `8–10`, но не `7♠` и не мизер. При победе на `10♣ без прикупа` объявление допускает `10♣/10♦/10♥/10NT без прикупа`, но не `10♠ без прикупа`.

## 3. Подтверждённые правила, реализованные в PR 2

1. Порядок ставок: 6♠–8NT, мизер, 9♠–9NT, мизер без прикупа, 10♠–10NT, 10♠–10NT без прикупа. Не вводить вымышленную 9 без прикупа.
2. Мизер только **первой собственной заявкой**. Мизер без прикупа — активному сопернику поверх обычного мизера либо прежнему мизеристу после перебивающей девятерной.
3. 10 без прикупа допускается как начальная заявка без обычной десятирной и перебивается более высокой мастью 10 без прикупа.
4. «Здесь» доступно третьему по очереди после ставки и паса, не на 6♠ и не на обоих видах мизера. Право выводится из истории и сохраняется до завершения торгов.
5. Пас окончателен в текущих торгах. Три паса без заявок → распасы.
6. Обычная игра и мизер с прикупом: открытые две карты, 12 карт до сноса, ровно две в скрытый снос. Безприкупные — свои десять, прикуп не раскрыт.
7. Первая карта обычной игры и мизера принадлежит первой руке. Дальше ведёт взявший взятку. Следовать масти обязательно, козырнуть при отсутствии масти и наличии козыря обязательно, перекозыривать необязательно.
8. На 6♠ оба защитника обязаны вистовать. На прочих контрактах сначала отвечает защитник слева от заказчика, затем второй; полвиста может заявить только второй после паса первого, только на 6/7. Первый может вернуться в вист.
9. Если вистует один, выбирает светлую/тёмную. В светлую он управляет рукой пасовавшего. Если первую карту ведёт заказчик, выбор светлой/тёмной игры происходит **после его первой карты**, до ответа защитников.
10. Если оба вистуют, защита тёмная. При мизере руки защитников открыты: до первой карты, если начинает защитник, или после первой карты заказчика, до ответов.
11. На распасах первые три взятки начинает первая рука; первые две задаются мастями первой и второй карт прикупа; козырей нет. Первая карта прикупа открыта до первой взятки, вторая — перед второй.
12. Проигрыш/успех контракта, гора, пуля, висты и итоговый рейтинг **не начисляются этим PR**: весь бухгалтерский расчёт относится к PR 3.

## 4. Отложенные функции и границы

- **PR 3:** все финансовые результаты, обязательные взятки защитников, «без трёх», подсад, полвиста, гора, пуля, помощь, итоговая математика. Текущее состояние `FINISHED` означает окончание карточного розыгрыша/решений защиты, но **не завершение финансовой партии**.
- **PR 4:** Firestore, серверная авторизация, роль игрока/комнаты, приватные `player_view`, согласованная доставка состояния, конкуренция версий и идемпотентность.
- **PR 5:** торговая панель в два клика, реальная игра для трёх браузеров, показ последней взятки всем участникам.
- **PR 6:** голосования об отмене карты/ставки, 120-секундный таймер, 180-секундный штрафной счётчик, «без трёх» UX, ручные исправления, передача управления открытыми руками на мизере, доказательство оставшихся взяток.
- Ни один `GameState`/`Deal`/`AuctionState` нельзя сериализовать прямо в клиент или общедоступную Firestore-коллекцию: они содержат закрытые руки, прикуп, скрытый снос и историю.
- В PR 2 **не подключается FastAPI-router и не меняются** `backend/app/main.py`, Dockerfile, Vercel/Firebase. Никакого нового endpoint по `/api/preferans`.

## 5. Пограничная ситуация распасов — проектное допущение

**На первых двух взятках распасов, когда ни один из трёх игроков не положил карту масти открытого прикупа**, подтверждённые правила не определяют победителя. В PR 2 предусмотрен **явный технический fallback**: побеждает старшая карта масти фактически первой сыгранной карты. Это **не подтверждённое историческое правило**; при разработке реальной игры его нужно согласовать и утвердить отдельно. Тест помечен именем `test_all_void_forced_suit_has_explicit_technical_fallback`.

Никакие другие внешние разновидности преферанса автоматически не подменяют домашние правила.

## 6. Проверки и сценарии

Тесты расположены только в `portfolio/preferans/tests/`. Они запускаются напрямую и включены в существующий `backend:check` через `backend/pyproject.toml` и `Taskfile.yml` (линтер/формат/compile). Новых Python-зависимостей **нет**. Сохранён существующий lock-файл.

```powershell
# repo root
Push-Location backend
uv run python -m pytest ../portfolio/preferans/tests -q
uv run ruff check ../portfolio/preferans/backend/src ../portfolio/preferans/tests
uv run ruff format --check ../portfolio/preferans/backend/src ../portfolio/preferans/tests
Pop-Location

task ci
```

**Проверенные на авторском отдельном окружении факты:** 184 теста (`pytest`) — PASS, компиляция исходников — PASS. **Не подтверждено:** общий `task ci` и GitHub Actions PR 2 — исполнять после применения к репозиторию пользователя. Тесты в том числе проверяют 50 детерминированных полных распасов, 50 шестерных на обязательном висте и 25 десятирных без прикупа; очередь, приватность невскрытого прикупа, невозможность нелегального хода и воспроизведение команд.

## PR24

`GameState.claim` хранит предложение всех оставшихся взяток, согласия, отказ и ранее сыгранные карты незавершённой взятки. При согласии реальная история `completed_tricks` сохраняется неизменной; остаток присуждается через `tricks_won`. `EndReason.ALL_MINE_ACCEPTED` проверяется в расчёте отдельно. При отказе руки, очередь, режим и текущая взятка сохраняются.
