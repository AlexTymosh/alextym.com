# PR 9 — выпуск кандидата, защита медиа и эксплуатация

**Проверенная исходная версия:** `main` после PR #275, `bae66e255f1e3a4a39a41f4c217c23545568a0eb`.

**Режим:** release candidate, **не production approval**. Выключенные по умолчанию флаги и ограничения доступа сохраняются. Реальные аккаунты, сети, эмуляторы и платные ресурсы автором патча не проверены.

## 1. Изменения

- WebRTC-сигнализация остаётся серверной и доступной исключительно участникам конкретной комнаты. Коллекции переименованы в `preferans_media` и `preferans_media_ops`, чтобы политика хранения не затронула одноимённые коллекции других проектов.
- Сигналы по-прежнему имеют максимум 90 секунд **доступности через API**, не гарантированное физическое удаление. `expires_at` — UTC timestamp, у медиасостояния срок 3 минуты без новых записей, у idempotency-операций 24 часа.
- `view` не возвращает просроченные документы и при истёкшем присутствии проецирует статус записи как `stopped`. Новая сессия не наследует прежнее согласие. Перезапуск версии медиадокумента не ломает курсор сигнализации.
- Браузерная локальная запись прекращается при ошибке опроса, устаревшем подтверждении согласий (watchdog 8 секунд), скрытии вкладки и событии offline. Никакой автоматической загрузки готового файла на сервер нет. При неожиданном отказе `MediaRecorder` серверу посылается `record_stop` best effort.
- Без активной записи WebRTC опрашивается примерно каждые 6 секунд вместо 2,5; во время голосования и записи — около 2,5 секунд. Сервер не принимает этот интервал как надёжное доказательство присутствия.
- Добавлен ручной ограниченный `cleanup_media.py` с режимом DRY-RUN по умолчанию и двойным подтверждением проекта для удаления. Он **не включается автоматически по расписанию**.
- Добавлены тесты изоляции комнат, сроков хранения, отказов, курса сигналов и безопасности локальной записи.

## 2. Важное ограничение тарифа £0

**Cloud Firestore TTL deletes не входят в бесплатную квоту и требуют billing.** Несмотря на наличие поля `expires_at`, **не включать** автоматическую TTL-политику при строгом бюджете £0. [Firebase: квоты](https://firebase.google.com/docs/firestore/quotas) и [политики TTL](https://firebase.google.com/docs/firestore/ttl).

Для бесплатного режима требуется регулярный ручной запуск очистки после игровой сессии и учёт остаточного риска при забытом запуске. Операция читает документы Firestore и расходует бесплатную квоту на чтения/удаления. Бюджетный контроль — задача владельца, не гарантия кода.

Команда **просмотра** на Windows PowerShell (из корня проекта):

```powershell
Push-Location backend
uv run python ../portfolio/preferans/backend/scripts/cleanup_media.py `
  --project-id YOUR_FIREBASE_PROJECT_ID --max-rooms 20 --max-deletes 100
Pop-Location
```

Команда **фактического удаления** — только после просмотра и проверки правильного Firebase-проекта:

```powershell
Push-Location backend
uv run python ../portfolio/preferans/backend/scripts/cleanup_media.py `
  --project-id YOUR_FIREBASE_PROJECT_ID --max-rooms 20 --max-deletes 100 `
  --apply --confirm-project-id YOUR_FIREBASE_PROJECT_ID
Pop-Location
```

Требуются разрешённые Google ADC credentials (`GOOGLE_APPLICATION_CREDENTIALS`) либо `FIRESTORE_EMULATOR_HOST` для эмулятора. В репозиторий нельзя коммитить JSON сервисного аккаунта. Вывод не содержит SDP, ICE, UID или ключи. Удаление использует серверное условие `LastUpdateOption`: если документ обновили после сканирования, операция не должна стереть новое состояние и остановится с ошибкой — повтори dry-run. Сканирование ограничено `max-rooms`; отсутствие найденных документов **не доказывает** отсутствие просроченных данных во всей БД. При большом количестве комнат нужен инвентаризированный процесс очистки по страницам.

**Миграция прежних тестовых комнат:** данные `preferans_rooms/{id}/media/current` и `media_operations` из PR 8 вручную удалить в тестовой базе перед релизом после проверки резервных копий; новый скрипт намеренно не трогает старые коллекции.

Если бюджет когда-либо изменится, отдельное решение о managed TTL можно рассматривать **только с billing** и оценкой стоимости; задержка физического удаления может составлять до 24 часов и больше. При £0 такую политику не включать.

## 3. Расход ресурсов и ограничение времени

Оценка **только нижней границы операций чтения** без логина, грантов, дополнительных экранов и ретраев:

| Режим | Расчёт для 3 игроков | Приблизительные чтения за час |
|---|---|---:|
| Медиа без записи, 6-секундный polling | 3 × 2 документа × 3600/6 | 3 600 |
| Медиа с записью, 2,5-секундный polling | 3 × 2 × 3600/2,5 | 8 640 |
| Игра, 8-секундный polling | 3 × 2 × 3600/8 | 2 700 |

Фактический расход может быть существенно выше из-за Firebase Project Grants, повторных запросов и остальной деятельности `alextym.com`. Firestore free tier — **50 000 document reads / day и 20 000 writes / day** в одной бесплатной базе, но лимит общий для проекта. [Firebase quotas](https://firebase.google.com/docs/firestore/quotas). Для четырёхчасовой видеозаписи суммарная **ориентировочная** нижняя граница `4×(8640+2700)=45 360` чтений, почти вся дневная бесплатная квота. Это **не измерение**. До включения медиа необходимо провести UAT с учётом реальных метрик.

## 4. Доступ, флаги и порядок запуска

1. Убедиться, что `task ci`, все 5 GitHub jobs и Docker build зелёные. `git status --short` пустой после коммита.
2. Проверить сохранение секретов только в настройках backend/frontend; Firebase rules остаются deny-all для браузерного SDK, сервер использует Admin SDK. Не вставлять секреты в `NEXT_PUBLIC_*`.
3. Тестировать **на staging или Firebase Emulator**, с тремя отдельными аккаунтами и явными грантами `preferans:Test` или `Admin`. `View` не может играть, посторонний не может просматривать чужие карты/сигналы, прямой доступ к Render защищён.
4. Временно включать `PORTFOLIO_LAB_ENABLED=true` и `PREFERANS_ROOMS_ENABLED=true` отдельно на frontend/backend **только в безопасной тестовой среде**. Для медиа требуется также `PREFERANS_MEDIA_ENABLED=true` на обоих серверах и `NEXT_PUBLIC_PREFERANS_MEDIA_ENABLED=true` в браузерной сборке. Изменение фронтенд-флагов требует новой сборки Next.js.
5. После проверок вернуть `PREFERANS_MEDIA_ENABLED=false` и `NEXT_PUBLIC_PREFERANS_MEDIA_ENABLED=false` до приёмки рисков. Публичную карточку каталога и indexability не включать до формального разрешения.
6. Проверить стоимость Firestore и план хранения сигналов. Если строгий £0 означает отсутствие даже потенциальных биллинговых обязательств, не включать managed TTL и платный TURN.
7. Для настоящего публичного запуска нужен подтверждённый Owner sign-off с приложенным чеклистом `PR09_UAT.ru.md` и скриншотами/логами без секретов.

## 5. Откат

- Самый быстрый отзыв доступа — одновременно установить `PREFERANS_MEDIA_ENABLED=false` на Render и Vercel, а `NEXT_PUBLIC_PREFERANS_MEDIA_ENABLED=false` — на frontend; задеплоить (публичный флаг вшивается в сборку).
- При инциденте с игровой логикой также отключить `PREFERANS_ROOMS_ENABLED` на обоих сервисах; сохранить данные до расследования, не удалять историю партий.
- Использовать Vercel/Render rollback на подтверждённый здоровый deployment. **Не** делать `git reset --hard` в рабочем репозитории и не удалять Firestore-результаты.
- Старые тестовые сигналы в `media` / `media_operations` и новое `preferans_media` требуют отдельной санитарной очистки после фиксации инцидента.

## 6. Известные блокеры полного релиза

1. Не доказано мгновенное прекращение записи на чужом устройстве в случаях зависшего JS, потери сети или злонамеренного поведения. Watchdog работает только пока браузер исполняет код; это не DRM и не защита от внешней записи экрана.
2. Нет TURN: связь через некоторые NAT может не установиться; нельзя обещать универсальное аудио/видео.
3. Не выполнена сквозная запись видео+звука и общего стола на трёх физических устройствах с воспроизведением файла; не проверены Safari/iOS и Android.
4. Нет автоматического **бесплатного** SLA на удаление сигнальных метаданных у полностью заброшенных комнат. Для £0 нужен регулярный операторский cleanup либо другая инфраструктура с измеримой стоимостью.
5. Не закрыты все исторические домашние правила: workflow «выбросить листик», выбор замены голого удара обычными, полный редактор набора правил и процедура исправления ошибочно раскрытой карты. Эти сценарии нельзя объявлять готовыми только потому, что чистый контракт тестируется.
6. Не выполнены live Firebase Emulator/production role matrix, трёхбраузерная партия, автоматическая проверка скрытых карт, восстановление после сбоев и замер Firestore/Render quota.

**Пока хотя бы один блокер остаётся, статус — release candidate; production флаги выключены.** Для небольшого закрытого теста с друзьями можно отдельно включить игру на staging и оставить медиа отключённым.
