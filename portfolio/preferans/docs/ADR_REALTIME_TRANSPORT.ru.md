# ADR — Preferans realtime transport

Дата: 24.11.2026. Статус: реализуемый кандидат PR10, приёмка не завершена.

## Контекст и решение
Существующий HTTP polling 8 с в активной игре (12 с вне игры) и pulse 45 с избыточно нагружают Firestore. Снижение интервала до 2 с умножает опросы на четыре. Firestore остаётся источником истины; клиентский Firestore SDK не получает новых разрешений. HTTP BFF сохраняет аутентификацию, CAS версии и идемпотентность. После успешного commit локальный hub публикует отдельный `seat_view` каждому участнику; никогда не пересылает `GameState` или raw Firestore документы. Новый сокет не принимает игровые команды.

- Next.js BFF выдаёт 30-секундный одноразовый ticket через существующую проверку session, grant, Origin. Backend проверяет seat/room и точный разрешённый Origin. URL WS строится из проверенного `BACKEND_ORIGIN`, без токена. Первый frame — authenticate; credential остаётся на сервере. Повторная проверка identity/grant/membership каждые 60 с, отзыв между проверками не мгновенный. HTTP mutations по-прежнему проверяются каждый запрос.
- Один Render instance/worker; hub и commit lock локальны процессу. На несколько процессов/инстансов распространять нельзя. Новая инфраструктура/Redis/платный relay не нужны. Проверить фактический `WEB_CONCURRENCY` и Docker command перед включением. При смене топологии выключить флаг, пока не появится согласованный транспорт.
- Heartbeat 15 с, WS lease 35 с, fallback HTTP lease 100 с. Закрытый socket отмечает потерю сразу после обнаружения сервером; при сетевой тишине — не позднее истечения lease при работающем сервере. Статус reconnecting до 60 с после обнаруженной потери; затем offline. Повторный вход и отсутствие сокета не отменяют отдельные причины паузы. HTTP fallback примерно 20 с, presence pulse 45 с, backoff подключения ограничен 120 с. Старая схема сохраняется при отключённом флаге.
- Pause state: независимые причины, сохраняем остаток счётчика и голоса. `undo_vote` блокирует ход, но не собственное голосование; внешняя пауза замораживает оба таймера. Durable checkpoint для активных часов примерно 60 с. При неизвестном offline-интервале freeze консервативно с последнего сохранённого наблюдения; это может дать больше времени, но не начисляет штраф за неизвестный простой. Реализация shared_overlay/break и last-trick atomic close относится к PR13, не этому PR.
- Одна последняя проекция на seat, ограниченные комнаты/tickets/handshakes, frame/response bounds и backoff. Нет бесконечного event queue. Повтор HTTP команды с тем же ключом не порождает новое действие. При сбое доставки после commit, повторная проверка версии/переподключение получает актуальный снимок.

## Альтернативы
Частый HTTP polling — прост, но расход растёт с длительностью независимо от игры. Firestore listener в браузере требует новой схемы раздельных разрешений и усложняет запрет раскрытия чужих рук. Vercel WebSocket Functions/внешний relay добавляют квоты/долгие executions. Для закрытой тройки выбрана локальная доставка на одном существующем Render, с явно ограниченным режимом эксплуатации.

## Риски и принятие
Проверить реальные revoke/expiry, CSP/connect-src, exact origin, restart, browser sleep, медленные соединения и three-seat privacy, сохранение версии и actual Firestore usage. Показатели hub — минимальные process-local оценки, не полный provider billing. p95 <=500ms — целевой показатель от commit до remote render, не гарантия. Никакого production включения до UAT. Видеозапись исключена по решению Owner; live WebRTC переносится в PR13.
