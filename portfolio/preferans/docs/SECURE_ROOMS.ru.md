# PR 4 — защищённые комнаты, Firestore и авторитетные команды

## 1. Границы и статус

PR 4 реализует **серверное API**, а не игровой интерфейс. Backend пакет `alextym-preferans` устанавливается как локальная зависимость общего FastAPI и копируется в Render Docker. Новые `/api/preferans/*` доступны **только при одновременно включённых** `PORTFOLIO_LAB_ENABLED=true` и `PREFERANS_ROOMS_ENABLED=true`. При выключенном флаге backend отвечает 404; новые публичные страницы, гранты или доступ к чужим комнатам не появляются.

Owner управляет комнатами на правах администратора, но без участия за столом не получает скрытые карты. Проектные роли Firestore: **View** — только GET в своей комнате; **Test/Admin** — GET/POST при наличии прав комнаты. Действующая роль проверяется **при каждом прямом запросе к Render**: Firebase bearer/session credential, admission и актуальный грант `preferans`. Next.js BFF повторяет проверку, требует сайтный HttpOnly cookie и Origin для любых POST; это не замена backend-authorize.

## 2. Хранилище (Admin SDK only)

- `preferans_rooms/{id}` — номер версии, ровно 3 места, admin UID, статус и текущая раздача, без карт.
- `preferans_rooms/{id}/private/current` — **только server Admin SDK**: полный `GameState` (руки, прикуп, снос, история) и `ScoreState` с фиксированным хешем правил. Никогда не отдавать напрямую.
- `preferans_rooms/{id}/events/{seq}` — открытый **очищенный** event (снос без карт, без скрытого seed).
- `preferans_rooms/{id}/operations/{hash}` — ответ идемпотентной операции; SHA-256 от UID и ключа, без передачи ключа в события.
- `preferans_create_ops/{hash}` — повтор создания комнаты возвращает тот же room ID.

**`infra/firebase/firestore.rules` не меняются: все клиентские чтения/записи запрещены.** Любые пользовательские проекции строятся только сервером после авторизации. Клиент никогда не получает сериализованный `GameState`, полный `Deal` или состояние чужой руки (кроме открытой руки по игровому правилу). Ключи Firebase Admin и приватные UID не попадают в общий event-журнал.

## 3. Команды и транзакционность

| HTTP | Путь | Назначение |
|---|---|---|
| POST | `/api/preferans/rooms` | Создать закрытую комнату и занять место 0 |
| POST | `/api/preferans/rooms/{id}/join` | Занять свободное место по секретному идентификатору |
| POST | `/api/preferans/rooms/{id}/start` | Начать/продолжить раздачу, только администратор комнаты |
| POST | `/api/preferans/rooms/{id}/commands` | `bid/pass/here/discard/declare/defense/mode/play/without_three` |
| POST | `/api/preferans/rooms/{id}/settle` | Рассчитать FINISHED-сдачу из PR 3, администратор |
| GET | `/api/preferans/rooms/{id}/view` | Проекция только для своей руки; `?since_version=N` — ответ `unchanged` |
| GET | `/api/preferans/rooms/{id}/events` | Последние публично безопасные события |

Каждый POST требует `idempotency_key` (8–128 символов), кроме того **все изменения существующей комнаты** требуют `expected_version`. Firestore транзакция читает receipt, room, private, применяет детерминированный переход и *атомарно* пишет новую версию, состояние, очищенное событие и receipt. Повтор той же команды с тем же ключом возвращает прежний ответ и не начисляет штраф/вист второй раз. Другой payload с тем же ключом отвергается (409); устаревшая версия — 409. Бизнес-ошибка — 422. Нет доступа — 401/403/404; SDK-ошибка — 503 без секретов.

Счёт считается после завершения каждой сдачи. При закрытии всех трёх пулей статус комнаты становится `closed` и дальнейшие сдачи запрещены. Переход от результатов к следующей раздаче разрешён администратору через `start`.

## 4. Поллинг вместо Firestore listener

Выбран **короткий опрос HTTPS (BFF)**: интерфейс PR 5 будет запрашивать `/view?since_version=N` примерно раз в 2–3 секунды, с адаптивным интервалом при ошибках. Это практичнее и безопаснее прямого Firestore SDK: текущие client rules закрыты полностью, нет дополнительных подписок, повторное подключение опирается на сохранённый `version`, а Render может проснуться после sleep. Сервер отвечает `unchanged` без чтения закрытой игры, если версия не изменилась.

Это **near-real-time polling**, а не SSE/Firestore push. При Render cold-start или сетевом сбое действия не теряются, но интерфейс может видеть задержку. Для выпускного решения измерить задержку, стоимость Firestore-чтений/записей, восстановление после 10–60 секунд офлайна и доступ с трёх браузеров.

## 5. Запуск и ограничения

- Для нового backend path package: выполнить `uv lock` в `backend/`, **включить `backend/uv.lock` в коммит**, затем `task ci`; Docker использует `uv sync --frozen`.
- Firebase Auth/Firestore Emulator покрыть интеграционными тестами до production (`firebase emulators:exec` и три реальных клиента), не считать unit fake transaction доказательством конкурентной безопасности SDK.
- Не включать `PREFERANS_ROOMS_ENABLED=true` в production до успешной проверки прямого Render 401/403, grants, emulator и трёх клиентов. Текущий PR по умолчанию fail-closed.
- Не выдумывать готовый realtime UI: полноценный интерфейс относится к PR 5.
- Принятые владельцем решения 1Б, 2А, 3А: `HOUSE_RULES_DECISIONS.ru.md`. Техническое распределение неделимой помощи требует пользовательского подтверждения перед публичным запуском.
