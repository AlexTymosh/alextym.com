# PR 5 — проверка полной игры на трёх браузерах

## Требуется до включения в production

1. Запусти Auth и Firestore Emulators с отдельным `demo-*` Firebase project ID, убедись, что оба backend и frontend используют одну и ту же безопасную локальную конфигурацию. Реальный production Firestore не должен быть затронут.
2. Создай три **разных** Firebase user и выдай каждому действующий проектный грант `preferans` (`Test`/`Admin`), убедись, что у всех выполнены требования admission. Owner может управлять комнатой, но не получать чужую руку.
3. В трёх независимых профилях браузера войди в Portfolio Lab, открой `/portfolio/preferans`. Первый игрок создаёт комнату, второй и третий открывают ссылку и нажимают «Занять место». При 409 второй вход должен обновить версию, не занимая два места.
4. Первый игрок начинает раздачу. У каждого 10 собственных карт, чужая рука скрыта, `GET /view`, `/events`, HTML и Network не содержат приватные карты и снос (кроме правилом открытой руки).
5. Проверь минимум одну обычную игру: торговля, «здесь», прикуп, снос, контракт, решения защиты, 10 взяток, результат, начало следующей раздачи.
6. Проверь распасы, мизер, 6♠, оба защитника пас, полвиста, светлую и тёмную игру, «без трёх» до первого хода. При светлой игре чужой открытой рукой управляет только вистующий.
7. Имитируй закрытие вкладки, reload, 30-секундный offline и рестарт backend. Восстановление происходит по URL комнаты, без повторного начисления и двойного хода.
8. Отправь одновременно две команды с одним `expected_version`: ровно одна изменяет состояние, другая получает 409. Дублируй тот же `idempotency_key` с прежним payload — не должно быть второй проводки.
9. Проверь из браузера авторизованного участника, пользователя без гранта, с ролью `View` и без cookie; проверь прямые POST на Render, а не только BFF. View не создаёт комнаты, приглашение не раскрывает владельцев/карты.
10. Убедись, что не менялись Fleet, Workforce, общие страницы, и все пять GitHub CI jobs зелёные. До выполнения этих пунктов оставь `PREFERANS_ROOMS_ENABLED=false` в production.

## Для локальной разработки

- На Vercel и Render нужны согласованные `PORTFOLIO_LAB_ENABLED`, `PREFERANS_ROOMS_ENABLED`, Firebase project/credentials, действующий Owner UID и гранты.
- В Next.js требуется `BACKEND_ORIGIN` (не URL с `/api`), а в Render корректный `FRONTEND_ORIGIN`.
- Клиентские Firestore правила должны оставаться закрытыми (`infra/firebase/firestore.rules` — `allow read, write: if false`).
- Firebase emulator credentials **никогда** не направляй к production project ID; см. `docs/architecture/portfolio-lab-identity-setup.md`.
- В полной локальной среде `task dev` запускает приложение; адрес страницы `/portfolio/preferans`.
