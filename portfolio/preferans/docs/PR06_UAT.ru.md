# PR 6 — тестовая приёмка

1. При чистом Git tree и после запуска форматтера/линтера выполнить `task ci`, проверить project/backend/frontend/rag/docker GitHub jobs. Факт прохождения CI нельзя заменять sandbox-результатами.
2. Запустить локальные Firebase Auth + Firestore emulators из `infra/firebase/firebase.json`, использовать тестовый `demo-` project и **три независимые** test-сессии с грантами `Test`/`Admin`. Проверить, что пользователи без гранта и `View` получают 403 для POST, а прямой Render без Firebase токена возвращает 401.
3. Создать новую комнату: установить 180/3/120, начать сдачу, поставить счётчик сопернику. Убедиться, что один серверный дедлайн видят все, второй счётчик отклонён, действие в 179.9 сек не наказано, в 180.0 сек начислен ровно 1 штраф, в 360.0 — 2.
4. На торговле запросить отмену последней ставки; проверить «да+да», «да+нет», тайм-аут, двойное голосование, второе действие до просьбы, двоих голосующих в гонке. Затем повторить для первой/второй карты, но **не** после завершённой взятки. Отмена не должна выдать приватный checkpoint.
5. В момент активного таймера отключить одного из трёх (вкладка, сеть, телефон); после истечения heartbeat lease должна возникнуть пауза, штрафы после момента паузы не начисляться. После возврата всех троих — сохранённое оставшееся время. Проверить пограничный короткий обрыв и документировать, что обнаружение не мгновенно.
6. Комната в `playing`: администратор +5 в гору игроку 2 с причиной, затем −5 компенсирующей записью. Все видят обе записи; неадминистратор — 403, повтор idempotency — один результат, конфликт версий — 409, изменения завершённой партии — 409.
7. Открыть `/events` и `/view` из трёх клиентов + Owner без места: нет закрытых рук, сноса, snapshots, UID, токенов. Сверить версии комнаты и private state до/после конкурирующих POST; Firestore rules по-прежнему deny-all клиентам.
8. Включить мониторинг количества Firestore reads/writes на 1 час при трёх активных пользователях. При риске превышения бюджета запретить production включение до перехода на оптимизированный transport.
9. После PR6 продолжаем PR7 (история, рейтинг, медали, графики), PR8 (WebRTC и согласие на локальную запись), PR9 (безопасность, offline SLA, нагрузки, полный UAT, документация релиза).
