# PR11 — новый игровой стол и подготовка комнаты

**База:** `2166e10cbcff19e743556917e000671cead87ba5`. PR10 merged; зелёный CI со слов Owner. Кандидат PR11; не деплой.

## Что изменилось

- `GameTable`, `CardArtwork`, `ProjectSidebar`, `Lobby`, `LobbySetup`: отдельные локальные компоненты, общий controller в PreferansGame. Игровой стол по часовой стрелке: при месте 0 слева 1, справа 2; при месте 1 слева 2, справа 0; при месте 2 слева 0, справа 1. Состояние движка и серверные seat IDs не меняются.
- Собственные карты снизу всегда, в том числе при игре за открытую руку. Открытые карты соперника показываются только из `open_hands`; при разрешённом `controller` и `legal_cards` можно выбрать карту непосредственно у соперника. Рубашки основаны только на `hand_counts` и не содержат скрытых ID. Прикуп во время торговли закрыт; открытые карты только из `widow`. Существующие команды и подтверждения остаются до PR12. Текущая взятка в центре; локальный предыдущий просмотр и таблица счёта в меню, пока не синхронизированные объекты.
- Аватар и ободок фактического действующего игрока (`controller` при открытых руках); присутствие из PR10. При fallback неизвестный статус серый. История/рейтинг загружаются при открытии; ранее включённые media доступны в меню, без кнопок создания записи. Видео рядом с игроками, магнитофон, общий лист и синхронная пауза — PR13. Нет дополнительных постоянных запросов к Firestore.
- Горизонтальный режим на телефоне; CSS-подсказка в portrait, состояние не демонтируется. Прокрутка вертикально допускается для длинной действующей панели, на коротких экранах и в меню. Полноэкранный игровой режим и новая компактная панель торговли — отдельная доработка PR12/14.

## Контракт лобби

GET `/api/preferans/rooms` (Test/Admin/Owner): две ограниченные single-field Firestore queries (seats array_contains UID, status lobby), до 100 документов каждая плюс 1 для признака усечения. Отдаёт `{rooms:[{room_id,status,occupied,mine}],can_create,truncated}`; только собственные незакрытые и доступные лобби, без UID, email и секретов. Усечение явно отображается, вход по ссылке/коду сохраняется. Сортировка собственные сначала, потом по времени создания среди прочитанных. Query выполняется при входе/ручном обновлении списка; не polling. Может потребоваться наличие стандартных single-field indexes; при ошибке fail-closed. POST create — только project Admin/Owner, Test не создаёт даже через прямой Render API.

GET `/api/preferans/rooms/{id}/profiles` (Test/Admin/Owner, только реальный член комнаты): 1 чтение room + до 3 profile reads. Отдельно от WS view, вызывается при входе и изменении occupancy. Только сохранённые first_name/last_name и upload WebP data URL, bounded. Нет fallback email или provider URLs; если IAM профилей отсутствует, UI показывает нейтральные места. Не меняем IAM автоматически.

Новые комнаты API имеют `lobby_setup`: три ready flags и первый сдающий. Команды `lobby_ready {ready:boolean}` и `lobby_config {dealer:0..2,target:1..1000}` через существующий транзакционный endpoint. Config только room admin до первой раздачи. Новый участник или изменение config/preset сбрасывает все ready. `start` блокируется пока все три true. Новая цель пули — новый immutable snapshot числовых правил до первого ledger entry, остальные формулы не изменяются. Default 20; 1..1000 — технический bound UI/validation, не изменение игровых формул. Старые лобби без marker сохраняют прежний старт для совместимости. Точная перестановка занятых мест требует обновления seat-bound tickets и согласия тройки; не реализована в этом кандидате. Историческое правило выбора проигравшего предыдущей партии того же состава остаётся отдельным workflow. Полноценный редактор наборов правил не добавлен.

## Rollback

Откат через revert squash-коммита, не удалять сохранённые комнаты и не изменять state вручную. Новое поле lobby_setup является добавочным; прежний backend его игнорирует, поэтому при откате в legacy UI гарантия readiness временно не действует. Не начинать новые партии на смешанных версиях frontend/backend. Стабильные Firestore ledger/results и PR10 transport не мигрируются. После merge зафиксировать версии обоих хостов, а после реального UAT продолжать PR12.
