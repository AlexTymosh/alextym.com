# PR 7 — неизменяемая история, медали, рейтинги, график

**База:** PR #273, squash `008ee18ee2b27f2c1fb8d7a15506a140090003e0`.

## Архитектура

- **Источник истины:** закрытый `ScoreState`, неизменяемый журнал расчётов в `preferans_rooms/{room}/private/current` и итоговая запись `preferans_results/{room_id}`.
- **Атомарная финализация:** создание результата `transaction.create` и обновление трёх `preferans_rankings/{opaque_player_id}` в **той же Firestore-транзакции**, где комната переходит в `closed`. Сохранение повторной операции с тем же idempotency key возвращает предыдущее решение и не даёт повторных медалей.
- **Один матч на комнату:** `room_id` — стабильный идентификатор завершённой партии; `game_id` меняется на каждой сдаче. Сервер сохраняет время начала первой сдачи, завершения последнего расчёта, количество сдач и hash правил.
- **Обратная совместимость:** у ранее созданных комнат отсутствует `started_at_ms`; `duration_ms = null`, а не ноль. Активное время без пауз не измерялось в PR 6, поэтому `active_ms = null`.
- **Доступ:** `GET /api/preferans/history?limit=1..100`, `GET /api/preferans/rankings`, `GET /api/preferans/results/{room_id}`. Они проходят те же Firebase Session и project-grant guards в FastAPI и Next.js BFF, что и остальные маршруты. Только закрытые итоги; данные чужих рук, UIDs и скрытых сносов отсутствуют.
- **Идентичности:** UI отображает стабильные 24-символьные псевдонимы, полученные из серверных UID, но реальные UID не отправляются в статистике. Согласование и отображение игровых имён — последующая задача.
- **Итоги:** нулесуммовые `net_results`, равные места по competition rank, двойное золото за делённое первое место, без золота при тройной ничьей. Правило `sheet_discarded` покрыто чистой функцией и тестами, но само действие «выбросить листик» пока не интегрировано в игровой workflow.
- **Миграция:** PR 7 автоматически фиксирует только партии, завершённые после установки. Уже закрытые старые комнаты не попадают в рейтинг без отдельно проверенного backfill; напрямую переписывать immutable результат нельзя.
- **Агрегаты:** отдельно по золоту, серебру, третьим местам, техническим поражениям, вистам, таймерным штрафам и ударам. Суммы хранятся по всем закрытым партиям, не зависят от пагинации истории. Полный рейтинг ограничен 1000 участниками (private trio); превышение выдаёт `503`, **не** усечённые результаты.
- **История:** лента максимум 100 последних партий за запрос, явный признак `has_more`; временной график строится по хронологии последних 100 партий и не выдаёт себя за статистику за всё время при `has_more=true`.

## Оставшиеся предметные пробелы

1. **Удары:** расчёт автоматически формирует базовые предполагаемые парные меры, но выбор игроком замены «1 голый → 10 обычных» отсутствует. В `GameResult` это явно обозначено `punches_confirmed=false`; значения предварительные. До полного релиза добавить подтверждение и immutable `PunchAward`-источник, чтобы рейтинг не выдавал предварительное за окончательное.
2. **Техническое поражение:** функция присуждения двух первых мест есть, но механизм принятого всеми «выбросить листик» отсутствует.
3. **Время:** `active_ms` невозможно вывести точно из старых данных и heartbeat-пауз без отдельного журнала интервалов.
4. **Игровые имена:** вместо подтверждённых display names используются стабильные псевдонимы.
5. **Firestore:** живые транзакции, составные квоты, индексы и многопользовательский UAT ещё необходимо проверить на Firebase Emulator.
6. **Масштаб:** прочтение рейтинга до 1000 игроков, график до 100 результатов. Для расширения за private trio нужны cursor pagination и выбор явной тройки.

**Схема хранения:** индексирование `finished_at_ms` в `preferans_results` и `gold` в `preferans_rankings` использует обычные одно-полевые индексы Firestore. Клиентские Firestore security rules не расширяются; чтение идёт только через подписанный backend.

**Безопасность:** сервер не сериализует `GameState`, `ScoreState` или Firebase UID в исторический API. Ledger SHA-256 служит checksum, не доказательством внешней честности или подписью.
