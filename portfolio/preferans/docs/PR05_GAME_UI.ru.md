# PR 5 — игровой интерфейс для трёх участников

**Основа:** PR #271 (защищённые комнаты, server-only Firestore). UI работает только при `PORTFOLIO_LAB_ENABLED=true` и `PREFERANS_ROOMS_ENABLED=true`; иначе остаётся прежняя информационная страница. Весь бизнес-расчёт и доступ определяет backend.

## 1. Возможности

- Создание комнаты, ссылка-приглашение с 32-значным идентификатором, вход второго и третьего участника.
- Экран трёх мест, старт раздачи администратором, состояние хода, прикуп, открытые руки, текущая и предыдущая взятка.
- Торговля с выбором минимальной заявки в два действия, пас, «здесь» по разрешению сервера, снос ровно двух карт, заказ контракта, вист/пас/полвиста, светлая/тёмная.
- Выбор карты и отдельное подтверждение её розыгрыша. Светлая рука управляется вистующим, но чужие закрытые карты не раскрываются.
- Сортировка карт перетаскиванием мышью и кнопками влево/вправо для touch и клавиатуры; порядок сохраняется в памяти вкладки, не записывается в Firestore или браузерное долговременное хранилище.
- Панель пули/горы/вистов и выбор пути начисления при закрытии сдачи.
- HTTP-поллинг `GET view?since_version=N`: около 3 секунд в игре, 6 секунд вне игры, 15+ секунд в скрытой вкладке; экспоненциальный backoff до 30 секунд при отказе.
- Обработка 401/403/404/409/422/502/503, повтор неизвестно завершившейся операции **с исходным `idempotency_key`**; 409 приводит к обновлению, а не автоматической отправке хода ещё раз.

## 2. Вход по приглашению

PR 4 не позволял незанявшему место игроку прочитать версию комнаты, необходимую для `join`. Поэтому добавлен узкий GET `/api/preferans/rooms/{id}/invitation`:

- требуется действующий Portfolio Lab user и проектный `Test` или `Admin` (либо Owner);
- возвращает только `room_id`, `version`, `status: lobby`, три булевых признака занятых мест;
- не возвращает UID, карты, историю, правила, счёт, владельца, скрытый прикуп или существующие игровые данные;
- после запуска партии — 404; клиентские Firestore Rules остаются `deny all`.

Присоединение по ссылке не заменяет grant: ID комнаты сам по себе не является авторизацией.

## 3. Новые публичные поля `/view`

- `dealer`, `first_hand`, `controller`, `is_passout`, `played_tricks`, `mode` — открытый игровой контекст.
- `legal_contracts` — только заказчику на этапе `declare`, по `legal_final_contracts`.
- `can_say_here` — только своему месту, вычисляется по `can_say_here` серверного аукциона.
- `score.target` — заданный набором правил размер пули.

**Недопустимо** добавлять `GameState`, `discarded`, чужие закрытые руки или `Firestore doc` в проекцию.

## 4. Операционные ограничения

- UI не включает таймеры, отмены с голосованием, правки счетов или медиасвязь: это PR 6/8.
- При выигрыше карт без розыгрыша, подсадах и распасах финансовую проводку инициирует администратор, после чего можно начать следующую сдачу.
- При настройках начисления, запрещённых бизнес-правилами, API ответит 422; UI не может отменить серверное решение.
- Серверные сценарии полвиста, мизера и отсутствия игроков проверяются вручную в браузерах.
- **Не заявлять готовность production** без Firebase Emulator, настоящих транзакций с тремя разными Firebase-аккаунтами и проверки прямого Render-origin.
